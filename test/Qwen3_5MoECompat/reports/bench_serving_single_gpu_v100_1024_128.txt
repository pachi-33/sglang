The old random dataset generator reports the requested 1024-token length before
decoding token IDs to text. Retokenizing that text in the server produced 988
tokens for the final request, so input-token throughput is based on the benchmark's
declared lengths. Output length was exactly 128 for every request because
ignore_eos=true.

The public API is non-streaming. bench_serving therefore observes the complete
response as its first chunk, making its printed TTFT/ITL/TPOT fields unsuitable
as per-token latency measurements. E2E latency and request/output throughput are
valid; the last_request_* values above come from the backend's internal token
timestamps.
