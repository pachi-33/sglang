## 问题与假设

研究从 EXP-0001 的 128 个请求中随机选择 k 个请求后，在单层内对全局专家 ID 去重，平均会形成多大的专家工作集。

假设：整条 256-token 请求的专家并集会很快覆盖绝大多数 256 个专家；在相同输出位置合并 k 个请求的口径下，跨请求重叠会使唯一专家数明显低于 `8*k`。

## 对照与变量

- 数据源：EXP-0001 聚合数据，shape `[128,256,40,8]`。
- 数据 SHA-256：`22464dc1e6f4e45c422dd14e10f3205f74bae252fcce91e167820da713cca7e6`。
- 独立变量：`k={1,2,4,8,16,32,64,128}`。
- 固定变量：Seed 0；请求内无放回抽样；每请求 256 个输出位置；40 层；每层 Top-8；256 个全局专家。
- 抽样：k=1 穷举全部 128 个单请求；k=128 使用全集；其余 k 各执行 500 次 Monte Carlo 子集抽样。
- 干扰因素：数据只包含 EXP-0001 的 128 个固定 prompt；不同输出位置不代表同时到达的线上请求。

## 指标定义

1. `whole_request`：对选中请求的全部 256 个输出位置，在每一层内取专家 ID 并集，再对随机子集和 40 层取平均。
2. `same_position`：对相同输出位置、相同层的 k 个请求取专家 ID 并集，再对 256 个位置、随机子集和 40 层取平均。

## 结果

| k | 整条请求：平均唯一专家/层 | 同位置：平均唯一专家/层 |
|---:|---:|---:|
| 1 | 154.045508 | 8.000000 |
| 2 | 202.596350 | 15.526751 |
| 4 | 235.035100 | 29.450452 |
| 8 | 249.732900 | 53.249020 |
| 16 | 254.428700 | 89.837217 |
| 32 | 255.608650 | 137.502688 |
| 64 | 255.924100 | 186.025225 |
| 128 | 256.000000 | 223.524121 |

- k=8 的整条请求并集已覆盖平均 97.55% 的专家；k=16 达到 99.39%，该口径快速饱和。
- 同位置口径下，k=8 的 64 次 Top-8 选择去重后平均剩余 53.25 个专家，说明存在约 16.8% 的跨请求重复选择。

## 结论与后续

假设成立。若研究整条生成过程所需的专家全集，k>=8 后几乎等于加载全部 256 个专家，区分度有限。若研究并发请求在单个 decode step 的合并换入量，应采用 `same_position` 口径；它能保留 k 增长时的跨请求路由重叠信息。
